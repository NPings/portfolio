Evaluating My Own Agent

Pivoting into AI evaluation work, I needed real reps, not theory. So I turned the practice on the system I actually depend on: the AI agent that runs my daily workflow, orchestrates my other agents, and routes work for me.

RoleDesigned, built & evaluated
ProjectPersonal practice, pivot portfolio
SubjectMy own daily-driver agent
ContextIndependent, not employer work
01

The problem

I was moving from UX research toward AI evaluation, and I knew that reading about rubrics and LLM-as-judge wasn't the same as doing it. I needed a real subject with real failure modes, not a toy dataset.

I had one close at hand: my own agent setup had real, specific complaints behind it. Work sometimes went out that should have been routed to a specialist instead. A request once landed with the wrong team. An entire capability got forgotten as if it didn't exist. None of that was measured. It was just a feeling that something was "off."

02

Challenges

Grading an agent's own words about its own behavior is a trap: an agent can write a perfectly reasonable-sounding reply while still calling the wrong tool underneath it, so judging the final text alone misses the actual defect.

A second trap was quota and cost. Full tracing on every exchange would be useful, but it is also the kind of always-on infrastructure that quietly becomes a recurring cost. I wanted evaluation and tracing I could reach for on demand, not a tap left running.

03

Approach

I built a practice repo grounded in real sources (MT-Bench, OpenAI's evals framework, Promptfoo's docs, published judge-reliability research) rather than guessing at method, and used it to run a sequence of increasingly real evaluations:

  • Black-box text grading with Promptfoo, wiring its exec provider to the actual CLI instead of a simulation, mixing deterministic checks with model-graded rubrics.
  • Tool-call trace inspection once I hit the ceiling of text grading: parsing the agent's own session logs for the specific tool call it made, so the assertion was "did it call the right tool" rather than "did it sound right."
  • Full trace review in LangSmith for the cases that needed a deeper look, built as an on-demand script rather than an always-on hook, so it only spends anything when I actually point it at a session.
04

What I built

Three linked pieces, each verified against real runs rather than taken on faith:

  • A regression suite covering the agent's own stated operating rules, run against fresh sessions so nothing carried over from conversation memory.
  • A real bug fix, found and confirmed with this method: the agent's own routing rules had gone stale and were missing two live specialist teams. I evaluated the complaint into three concrete, testable scenarios, confirmed the defect with real extracted tool-call evidence, had it fixed, then reran the exact same suite as a before/after check.
  • An on-demand tracing tool that pulls one specific session on request and loads it into LangSmith for deep inspection, with a final secret-scanning gate in front of anything sent out, built and verified through its own scope-build-verify pipeline with an independent red-team pass.
05

How it works

Local session logs Every exchange is already recorded locally, for free, by default
→
Promptfoo eval Deterministic + LLM-rubric grading against fresh runs
→
On-demand trace Secret-gated, sent to LangSmith only when flagged
→
Fix & regression test Same suite, rerun, to prove the fix actually held
06

Outcomes

11/14Pass rate on the first full regression pass, isolating one real formatting tic, not a substance problem
2/2Routing scenarios confirmed fixed with real extracted tool-call evidence, not just a cleaner-sounding reply
0Raw secrets reached the trace, confirmed against a probe built specifically to slip past the existing redaction

The eval found and helped fix a real routing defect, confirmed with tool-call evidence rather than a feeling. It also surfaced one useful false lead along the way: a deterministic check once flagged the agent for "recommending" a platform it had actually correctly warned against, which became a concrete lesson about when a model-graded rubric earns its keep over a keyword match.

07

What I learned

Grading the final answer only tells you whether it sounds right. You have to look at what the agent actually called to know whether it did the right thing.

The same discipline that makes a UX finding credible, defining the question before picking the method, and demanding evidence over impression, carries over directly into evaluating an AI system. The tools changed. The standard of proof didn't.
